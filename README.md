# Bug 猎人

> 你不能改它的代码，只能写测试让它现形。

一个命令行 + 网页两版的小游戏：21 个关卡，每关一段「能正常运行」的代码，里面藏着一个 bug。玩家不能修改这段代码，只能写 pytest 测试让 bug 暴露出来。判题由程序完成：同一份测试会在「有 bug 的版本」和「修复后的版本」上各跑一遍，两遍结果都符合预期，才算过关。

## 为什么这条规则有意思

判题是双条件的，两个条件**同时**满足才算过关：

1. 你的测试在**有 bug 的版本**上失败
2. 同一个测试在**正确版本**上全部通过

为什么要第二条：`assert False` 也能让第一条成立。只满足第一条的测试会天天误报，而现实里测试工程师犯得最多的错不是漏测，是写出一个所有人都忽略的红色。

只满足第二条同样不行——那说明测试什么都没断言到（空转）。

所以这个游戏训练的不是「怀疑一切」，是「精准」：让测试恰好打在出错的那条路径上，其余路径全部放行。

## 安装

本项目尚未发布到 PyPI，当前只能从源码安装。需要 Python 3.10+。

```bash
git clone https://github.com/qwqianli/bug-hunter.git
cd bug-hunter
pip install -e ".[dev]"
```

装完即可使用 `bug-hunter` 命令。要在浏览器里玩本地版，再装 Web 依赖：

```bash
pip install -e ".[web]"
```

## 开始玩

```console
$ bug-hunter list
共 21 关 · 已完成 0 / 21

boundary 边界值
  [1] 001-off-by-one          差一
  [1] 006-initial-value       起点
  [2] 007-single-element      只有一个

exception 异常流
  [2] 002-empty-input         空
  [2] 008-out-of-range        越界
  [3] 009-wrong-type          错误的类型

（isolation / numeric / contract / sideeffect 四组同理，此处省略）
```

进一关，游戏会把有 bug 的代码放进当前目录的 `_playground/target.py`：

```console
$ bug-hunter play 001-off-by-one
差一  ·  难度 1

find_max 应该返回列表里最大的数。它大多数时候是对的。

─────────────────────────────────────
我在 _playground/target.py 里放好了代码。
你的任务：在 _playground/ 里写一个 test_*.py，让它抓到这个 bug。

写完运行：
  bug-hunter submit 001-off-by-one _playground/test_你的名字.py

卡住了就运行：
  bug-hunter hint 001-off-by-one
```

在 `_playground/` 里写一个测试文件（名字以 `test_` 开头）：

```python
# _playground/test_mine.py
from target import find_max

def test_max_at_last():
    assert find_max([1, 3, 5]) == 5
```

提交判题：

```console
$ bug-hunter submit 001-off-by-one _playground/test_mine.py
过关 ✓

你的测试精准地抓住了这个问题，而且没有冤枉正确代码。
这正是测试该有的样子：只针对出错的那条路径。

下一关：bug-hunter play 006-initial-value

$ bug-hunter list
共 21 关 · 已完成 1 / 21

boundary 边界值
  [1] 001-off-by-one          差一    ✓
  [1] 006-initial-value       起点
```

过关进度存在 `~/.bug-hunter/progress.json`，关掉终端下次还在。七种判题结果对应七种不同的提示（过关 / 没抓到 / 误报 / 没有测试被执行 / 测试代码有问题 / 超时 / 判题器出错），看提示就知道下一步该改什么。

## 在浏览器里玩

除了命令行，还有两个网页版本：

- **本地版**：`bug-hunter web`（默认端口 8765，加 `--no-browser` 不自动打开浏览器），打开 `http://127.0.0.1:8765/`。判题在你本机完成，服务只监听本机回环地址，只用于本机。
- **在线版**：https://qwqianli.github.io/bug-hunter/ ——打开后浏览器要用 Pyodide 在页内搭起一套 pytest 环境来判题，首次打开要等冷加载（实测约 21～181 秒，视网络状况而定，需要浏览器支持 WASM），之后判题全部在浏览器内完成，不读取你的本地文件。

两版玩法一致：进关 → 写 `test_` 开头的测试 → 提交判题 → 过关。

## 21 个关卡

按六类测试技能分组，`list` 的显示顺序与此相同：

### boundary 边界值——错误藏在位置的两端

| 编号 | 标题 | 难度 | 教什么 |
|---|---|---|---|
| 001-off-by-one | 差一 | 1 | 循环少走最后一个元素，最大值在末位时才暴露 |
| 006-initial-value | 起点 | 1 | 用 0 初始化最大值，全负数列表会返回错误结果 |
| 007-single-element | 只有一个 | 2 | 「对半分」的直觉在长度为 1 时失效 |
| 016-capacity | 容量 | 2 | 「最多存 N 条」的边界在第 N+1 条：`<=` 放过了满的那个位置 |

### exception 异常流——合法但罕见的输入必须被想到

| 编号 | 标题 | 难度 | 教什么 |
|---|---|---|---|
| 002-empty-input | 空 | 2 | 空列表触发除零崩溃，期望行为是返回 None |
| 008-out-of-range | 越界 | 2 | 索引超出范围时崩溃，负数索引也算越界 |
| 017-blank-string | 全空白 | 2 | 真值判断放过 `"   "`——非空但无内容的输入也要拒 |
| 009-wrong-type | 错误的类型 | 3 | 带空格的数字字符串被当成非法输入拒掉 |

### isolation 测试隔离——测试之间不能互相影响

| 编号 | 标题 | 难度 | 教什么 |
|---|---|---|---|
| 003-stateful | 第二次 | 3 | 可变默认参数让两次调用共享同一个列表 |
| 010-cache | 缓存 | 3 | 模块级缓存让第二组参数命中旧结果 |
| 011-order | 顺序 | 4 | 模块级列表让后一个测试被前一个污染 |
| 018-tmp-file | 残留 | 4 | 两个测试各自能过、一起跑就挂：共享的是文件系统，不是内存 |

### numeric 数值精度——计算机的算术不等于数学的算术

| 编号 | 标题 | 难度 | 教什么 |
|---|---|---|---|
| 012-integer-division | 整数除法 | 2 | `//` 是截断不是四舍五入 |
| 019-float-sum | 凑满 | 3 | 十笔 0.1 一笔一笔累加，再用 `==` 判等会被误差咬（加出来是 0.9999999999999999） |
| 004-is-zero | 相等 | 4 | 浮点运算的结果不能用 `==` 精确比较 |

### contract 类型与契约——返回值的约定不能漂移

| 编号 | 标题 | 难度 | 教什么 |
|---|---|---|---|
| 013-no-value | 没有值 | 3 | 链式 `.get` 在中间层缺失时崩溃，None 会传播 |
| 005-two-answers | 两种答案 | 5 | 失败路径返回 None 而不是约定好的 0 |
| 020-container-type | 换容器 | 5 | `[...] or ()` 让返回值类型随内容变化：契约要求一直是 list |

### sideeffect 副作用——依赖外部世界的代码不可测

| 编号 | 标题 | 难度 | 教什么 |
|---|---|---|---|
| 015-no-order-guarantee | 顺序不保证 | 3 | 返回值依赖字典插入顺序 |
| 021-no-seed | 洗牌 | 3 | 函数体内部自己 `random.seed()`，外部种子管不住它 → 结果不可复现 |
| 014-today | 今天几号 | 4 | 函数内部自取「今天」，结果每天不同、无法断言 |

## 命令

| 命令 | 作用 |
|---|---|
| `bug-hunter list` | 按分类列出全部关卡和完成状态 |
| `bug-hunter play <关卡id>` | 进关：显示介绍，把有 bug 的代码放进 `_playground/` |
| `bug-hunter submit <关卡id> <测试文件>` | 判题：双条件通过才算过关，进度自动保存 |
| `bug-hunter hint <关卡id>` | 提示逐条给出，每运行一次多给一条 |
| `bug-hunter answer <关卡id>` | 看这一关的参考测试（看过答案的关不计入完成数） |
| `bug-hunter web [--port 8765] [--no-browser]` | 在浏览器里玩：启动本地版服务，只绑 127.0.0.1 |

## 已知限制

- 关卡代码对玩家可读，理论上可以针对代码内容定制测试。不做防御——作弊损害的是作弊者自己的练习。
- 只支持 pytest，不支持 unittest 或其他测试框架。
- 判题在本地执行，不做沙箱隔离：测试代码就是本机代码，不要用这个游戏运行来路不明的关卡。
- 进度存档没有文件锁，两个终端同时玩会互相覆盖。
- 在线版在浏览器内用 Pyodide 跑 pytest：需要浏览器支持 WASM，首次打开有冷加载等待（实测约 21～181 秒，视网络状况而定），判题行为与本地版一致，但不读取你的本地文件。
- 本地版 `bug-hunter web` 会在 `127.0.0.1:8765` 起一个无鉴权的本地服务，只用于本机；测试代码在本机直接执行，无沙箱隔离。
- 在线版是 `gh-pages` 分支里的构建产物，由部署流程生成，本地新提交的内容不会自动出现在线上。
- `bug-hunter` 包尚未发布到 PyPI，安装只有上文源码方式一种。

## 自己出题

关卡是 YAML 数据，不是代码。每一关的字段说明、难度判定标准、六类教学点的完整定义和新增关卡流程，见 [docs/关卡设计规范.md](docs/关卡设计规范.md)。

写完一关跑两道检查：

```bash
python scripts/check_levels.py                  # 每关的参考测试必须真的能过关
python -m pytest tests/test_levels_content.py -v # id 唯一、难度有梯度、内容不重复
```
